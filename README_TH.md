# NIEMS Project Intelligence Management 2570

## สถานะของโปรแกรม
Dashboard แบบ Interactive HTML ใช้งานได้บนเบราว์เซอร์ รองรับการค้นหา กรองข้อมูล แก้ไขข้อมูลบันทึกจริง เพิ่มสัญญา บุคลากร การมอบหมาย ผลสัมฤทธิ์ ประเด็นความเสี่ยง บันทึกผลรายเดือน และแนบหลักฐานในเบราว์เซอร์ รวมทั้งส่งออก/นำเข้าข้อมูล JSON และส่งออก CSV

**สำคัญ:** รุ่นนี้เป็น Static / Offline-ready Dashboard จัดเก็บข้อมูลเพิ่มเติมใน `localStorage` และไฟล์หลักฐานใน `IndexedDB` ของเบราว์เซอร์แต่ละอุปกรณ์ ไม่ได้มีฐานข้อมูลกลางหรือระบบแบ่งสิทธิ์หลายผู้ใช้ จึงยังไม่ใช่ระบบบริหารงานส่วนกลางที่ใช้งานร่วมกันหลายอุปกรณ์โดยอัตโนมัติ ห้ามตีความว่าระบบได้เชื่อมต่อ e-GP, EMS Portal, e-Finance, ระบบบุคลากร หรือคลาวด์ของ สพฉ. แล้ว

## เริ่มต้นใช้งาน
1. เปิด `index.html` ผ่าน Chrome, Edge หรือ Safari รุ่นปัจจุบัน (สำหรับบันทึกข้อมูลระยะยาวแนะนำให้ใช้งานจาก HTTPS เช่น GitHub Pages แทน `file://` เพราะนโยบายเก็บข้อมูลของแต่ละเบราว์เซอร์อาจต่างกัน)
2. เมนู **ภาพรวมบริหาร** แสดง KPI และแผนงบประมาณจากเอกสาร 2 ฉบับ
3. เมนู **จัดซื้อจัดจ้าง** คลิกแต่ละรายการ แล้วกรอกสถานะ ผู้รับผิดชอบ และยืนยันการเชื่อมโยงภารกิจที่เกี่ยวข้อง
4. เมนู **แผนงานรายเดือน** คลิกช่องรายเดือนเพื่อบันทึกผลจริง แยกจากสีระดับกิจกรรมตามแผน
5. เมนู **สัญญา**, **กำลังคน**, **ผลสัมฤทธิ์**, **หลักฐาน** และ **ความเสี่ยง** ใช้สำหรับกรอกข้อมูลจากเอกสารหรือผลการปฏิบัติงานจริง
6. กด **สำรองข้อมูล** หลังกรอกข้อมูลแต่ละครั้ง เพื่อเก็บไฟล์ JSON ที่รวมข้อมูลและไฟล์หลักฐานที่ระบบเรียกอ่านได้
7. เมนู **ศูนย์ข้อมูลและประวัติ** สามารถกู้คืนไฟล์สำรอง JSON ได้ โดยการนำเข้าจะแทนข้อมูลของเครื่องนั้น

## โครงสร้างข้อมูลเริ่มต้น
- แผนปฏิบัติงาน: 35 ภารกิจ (ITCO 23 และ NDEMS 12) × 12 เดือน
- จัดซื้อจัดจ้าง: 33 รายการ วงเงินรวม 110,502,300 บาท
- งบลงทุน: 67,932,300 บาท (9 รายการ)
- งบดำเนินงาน: 42,570,000 บาท (24 รายการ)
- ตามรายการต้นฉบับมีร่าง TOR 31 รายการ และไม่มีร่าง 2 รายการ (ลำดับ 14 และ 15)
- เป้าหมายเชิงปริมาณในภาพ: RNIS ขยายเพิ่ม 29 จังหวัด แต่ยังไม่มีผลสำเร็จจริงในชุดข้อมูล

ข้อมูลสถานะจริง สัญญา กำลังคน และการเบิกจ่ายเริ่มต้นเป็นค่าว่าง ไม่ได้สมมติผลการดำเนินงานเป็น 0 หรือ 100%

### แหล่งอ้างอิงในชุดไฟล์
- `source_action_plan_2570.jpg` ภาพ YEAR ACTION PLAN 2570 ของสำนักดิจิทัลการแพทย์ฉุกเฉิน
- `source_procurement_2570.pdf` แผนจัดซื้อจัดจ้างปีงบประมาณ 2570 จำนวน 33 รายการ
- `source_data.json` ข้อมูลที่ถอดจากสองแหล่ง พร้อม `proposedLinks` ซึ่งเป็น **การจับคู่เชิงวิเคราะห์ที่ยังไม่ยืนยัน**

**ข้อจำกัดของการถอดแผนรายเดือน:** ค่าระดับกิจกรรม 1–3 ใน `source_data.json` เป็นการถ่ายทอดสีจากภาพต้นฉบับในเชิงภาพโดยประมาณ มิใช่ข้อมูลผลการดำเนินงานจริง ไม่ควรใช้อ้างอิงเป็นหลักฐานว่าภารกิจดำเนินการเสร็จแล้ว

## อัปโหลดไป GitHub Pages
1. สร้าง Repository ใหม่ (ควรตั้งเป็น Private ถ้าใช้ข้อมูลการบริหารภายใน) 
2. วาง `index.html` ไว้ที่ root ของ Repository แล้ว Commit
3. เปิด GitHub Pages ในส่วน Settings → Pages ตามสิทธิ์ของบัญชี
4. ถ้าต้องการแสดงข้อมูลภายในหรือข้อมูลที่ไม่เปิดเผย ไม่ควรเผยแพร่ Dashboard พร้อมข้อมูลจริงบนเว็บไซต์ Public
5. แม้เว็บไซต์มี HTTPS ข้อมูลที่ผู้ใช้กรอกก็ยังเก็บเฉพาะในเบราว์เซอร์เครื่องนั้น ไม่ซิงค์ไป GitHub หรือผู้ใช้อื่น

## แนวทางสำหรับนำไปใช้เป็นระบบกลางหลายผู้ใช้
ไฟล์ `schema_production.sql` เป็น **แบบร่างโครงสร้าง PostgreSQL สำหรับทีมพัฒนาประกอบการออกแบบ** ไม่ได้เชื่อมกับ Dashboard ปัจจุบัน การนำขึ้นระบบกลางต้องพัฒนา Backend API, SSO/RBAC, Row Level Security, object storage, audit log ที่แก้ไขย้อนหลังไม่ได้, backup/restore, logging, encryption และแนวทาง PDPA/ISMS ตามการอนุมัติขององค์กรก่อนใช้งานจริง

## ข้อควรระวังด้านข้อมูล
- ไม่ควรบันทึกข้อมูลส่วนบุคคลหรือข้อมูลผู้ป่วยที่ไม่เกี่ยวกับการติดตามโครงการ
- ควรจำกัดการเข้าถึงไฟล์สำรองซึ่งอาจมีชื่อบุคลากรหรือเอกสารภายใน
- ผลสำเร็จทางการเงินและผลการดำเนินงานต้องอ้างอิงข้อมูลตรวจรับ/ใบสำคัญจ่าย/รายงานผู้รับผิดชอบจริง
- การมีร่าง TOR ในเอกสารตั้งต้นไม่แปลว่า TOR ผ่านการเห็นชอบหรือพร้อมประกาศจัดซื้อจัดจ้าง


## ปรับปรุงการแสดงผล Kanit Large UI (26 ตุลาคม 2569)
- ปรับตัวอักษรทั้งหมดให้ใช้ฟอนต์ Kanit จาก Google Fonts และมีฟอนต์สำรองกรณีออฟไลน์
- ขยาย KPI ตาราง กราฟ Gantt เมนู ตัวกรอง ป้ายสถานะ แบบฟอร์ม และหน้าต่างแก้ไขข้อมูล
- เพิ่มปุ่ม A− / A+ เปลี่ยนขนาดจากฐานที่ขยายแล้ว 100%, 110%, 120% โดยบันทึกการตั้งค่าในเครื่อง
- ไม่เปลี่ยนข้อมูลแผน ข้อมูลจัดซื้อจัดจ้าง สูตรคำนวณ หรือวิธีบันทึกผลจริง
- ครั้งแรกที่เปิดใช้งานควรมีอินเทอร์เน็ตเพื่อโหลด Kanit จาก Google Fonts หากออฟไลน์จะใช้ฟอนต์สำรองจากเครื่องจนกว่า Kanit จะพร้อมใช้งาน
